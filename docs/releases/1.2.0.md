# Radixing Traffic Engine 1.2.0

Deployment-local Web runtimes can now refresh public network and crawler data using the same adapters as the standalone Node service. A separate `@radixing/traffic-engine/web` entry removes the need to copy parsing and source validation into a host-specific publisher.

- Explicit source selection, bounded HTTPS fetch and standard gzip decompression.
- Shared CIDR, crawler, ASN and country parsing; Web Crypto source hashes and schema-1 snapshot IDs compatible with 1.1.
- Previous source metadata alone supports minimum-count and record-drop checks.
- Smaller Web defaults plus configurable download, expansion, record and canonical-size bounds.
- Optional awaited host validation hook for shard/lookup acceptance before returning a candidate; no complete lookup compilation on the Web path.
- Node API/defaults preserved, including full lookup compilation before file publication.
- Browser bundle and actual workerd tests without Node compatibility, plus Node/Web parity and failure-path tests.

This release provisions no scheduler or storage and changes no routing policy, scanner thresholds or request-time model behavior. Hosts own locks, immutable shard publication, activation, freshness and rollback. No deployment data, bindings or credentials are included. See the [Web updater contract](../web-updater.md) for integration and validation boundaries.

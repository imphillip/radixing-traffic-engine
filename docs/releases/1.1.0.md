# Radixing TDS 1.1.0

Scanner defenses are now standard supporting functionality for paid-traffic ingress. Sensitive targets terminate with 404 and trusted path-enumeration evidence terminates with 403 before feature enrichment or project routing. A project catch-all redirect cannot override these guards.

- Enable the five-category sensitive-path catalog by default; strengthen raw/encoded path normalization in probe catalog version 2.
- Enable standalone per-host/trusted-IP tracking: 60 requests and 40 distinct paths in 15 seconds, with a fixed 60-second cooldown.
- Bound local state to 4096 sources by default, store source/path hashes, expire idle states and expose unavailable tracking coverage.
- Preserve the pure synchronous core: embedded hosts provide trusted enumeration evidence and maintain their own isolated state.
- Add independent explicit runtime overrides, stable protection IDs and versioned decision evidence.
- Document default behavior changes, shared-IP and replica limitations, host responsibilities, and English architecture diagrams.

Bot, VPN, datacenter and geography labels do not create default blocking rules. No Jev, LLM, model API keys, new external datasets or private hosting configuration are introduced. This is supporting scanner protection, not a managed WAF or DDoS service.

Read [scanner protection and migration](https://github.com/imphillip/radixing-traffic-engine/blob/v1.1.0/docs/scanner-protection.md) before upgrading. Independently pinned hosted services require their own tested adoption release.
